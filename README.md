# frank body — Design Studio (frank Create)

A [TanStack Start](https://tanstack.com/start) app for generating and reviewing brand
imagery and video, backed by Lovable Cloud. It also hosts an MCP server so agents such
as Claude can drive the studio.

- App source: `src/`
- Backend: Lovable Cloud (`supabase/functions/frank-api`, `supabase/migrations`)
- MCP server: `src/lib/mcp/` — registered via `.lovable/mcp/manifest.json`
- Brand assets: `brand guidelines/`

## Local development

```bash
npm install
npm run dev     # serves the app on port 8080
npm run build   # production build
npm test        # vitest
```

## Server routes

These are real server routes, not client-side paths. They only work because the app is
server-rendered — a static build cannot answer them.

| Path | Purpose |
| --- | --- |
| `/mcp` | MCP streamable-HTTP endpoint (OAuth protected) |
| `/.well-known/oauth-protected-resource` | RFC 9728 protected-resource metadata |
| `/.mcp/list-tools`, `/.mcp/invoke-tool/$tool` | REST companions for the MCP proxy |
| `/.lovable/oauth/consent` | Connector consent screen |
| `/lovable/email/queue/process` | Email queue drain, called by `pg_cron` |

The MCP and OAuth-metadata routes are generated by the `@lovable.dev/mcp-js` Vite plugin
and carry an `AUTO-GENERATED` banner — edit `src/lib/mcp/index.ts` instead.

## Build contract

**`vite.config.ts` must keep using `@lovable.dev/vite-tanstack-config`.** That wrapper
runs Nitro with the `cloudflare-module` preset, which is the only thing that inlines
dependencies into the deployed worker and emits `dist/server/wrangler.json`.

The publish target is a Cloudflare Worker with **no `node_modules`**. A plain
`tanstackStart()` build externalises dependencies instead of bundling them, so the
worker dies at cold start with `Error: No such module "<pkg>". imported from
"server.js"` and *every* route returns 502 — the app, `/mcp`, and OAuth discovery alike.
Chasing that by adding package names to `ssr.noExternal` never terminates; each publish
just reveals the next transitive dependency.

`npm run build` therefore ends with `scripts/check-server-bundle.mjs`, which fails the
build if anything under `dist/server/` still imports an unbundled bare specifier, or if
`dist/server/wrangler.json` / `dist/client/` are missing.

Expected output layout:

```
dist/client/         static assets
dist/server/         self-contained worker + wrangler.json
```

To reproduce Lovable's exact production build locally, set `LOVABLE_SANDBOX=1`:

```bash
LOVABLE_SANDBOX=1 npm run build
```

Without it the local build may target Node instead of Cloudflare, which is what made
earlier local checks pass while production stayed broken.
